# Story 1.15 — Painel Admin de Gerenciamento de Usuários

**Status:** Ready for Review
**Epic:** 1 — IcognitoChat MVP
**Story:** 1.15
**Depende de:** 1.2, 1.10

---

## Descrição

Como administrador, quero visualizar todos os usuários cadastrados, ver quando cada um foi visto pela última vez, e poder remover contas, para que eu tenha controle sobre quem pode acessar o sistema.

---

## Contexto Técnico

Hoje o admin só consegue criar usuários via `POST /api/auth/admin/users`. Não há listagem, não há exclusão, não há visualização de atividade. Com o banco persistindo, usuários se acumulam sem controle.

A UI pode ser uma seção na tela de login (visível apenas quando autenticado como admin) ou uma rota dedicada `/admin`.

---

## Critérios de Aceitação

- [ ] Rota `GET /api/auth/admin/users` retorna lista de usuários com `{ id, username, created_at, last_seen_at }` (sem `password_hash`)
- [ ] Rota `DELETE /api/auth/admin/users/[id]` remove um usuário pelo ID (requer autenticação admin via `MASTER_PASSWORD`)
- [ ] Página `/admin` (protegida por `MASTER_PASSWORD` via sessão admin separada ou query param) exibe:
  - Tabela de usuários com username, data de criação, último acesso
  - Botão de remover por usuário (com confirmação)
  - Formulário de criação de novo usuário (já existente, migrar para cá)
- [ ] Admin não pode remover a si mesmo se houver sessão ativa
- [ ] Após remoção, usuário removido é desconectado do Socket.io se estiver online

### Achado: FK Constraint — Deleção de usuário falha se houver mensagens

**Severidade:** HIGH
**Arquivo:** `src/app/api/auth/admin/users/[id]/route.ts:26`

**Problema:** `DELETE FROM users WHERE id = ?` falha com `FOREIGN KEY constraint failed` quando o usuário tem mensagens no banco. A tabela `messages` declara `user_id REFERENCES users(id)` sem `ON DELETE CASCADE`, e `foreign_keys = ON` está ativo. O handler não trata esse erro, resultando em HTTP 500 silencioso — a UI exibe falha sem feedback adequado.

**Fix necessário:** Antes de deletar o usuário, deletar suas mensagens:
```sql
DELETE FROM messages WHERE user_id = ?  -- antes de DELETE FROM users
```

**Subtarefa adicionada:** `[x] Fix FK: deletar mensagens do usuário antes de deletar o usuário em DELETE /api/auth/admin/users/[id]`
