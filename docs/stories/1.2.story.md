# Story 1.2 — Autenticação: Senha Mestra + Geração de Usuários

**Status:** Done
**Epic:** 1 — IcognitoChat MVP
**Story:** 1.2
**Depende de:** 1.1

---

## Descrição

Como admin, quero usar a senha mestra para criar pares {usuário, senha} aleatórios para meus amigos, para que eles possam fazer login sem eu precisar revelar a senha mestra. Como usuário, quero fazer login com usuário e senha na tela inicial.

---

## Critérios de Aceitação

- [ ] Tela de login (`/`) com campos usuário e senha
- [ ] Login com credenciais válidas cria sessão JWT (cookie httpOnly)
- [ ] Login inválido retorna erro claro
- [ ] Rota `POST /api/auth/admin/users` protegida por `MASTER_PASSWORD` no header
- [ ] Admin pode gerar usuário com: username aleatório (ex: `fox-7k2m`) e senha aleatória (8 chars alfanumérico)
- [ ] Senhas armazenadas com hash bcrypt (10 rounds) no SQLite
- [ ] Rota `POST /api/auth/login` valida credenciais e retorna session cookie
- [ ] Rota `POST /api/auth/logout` destroi a sessão
- [ ] Middleware protege `/chat/*` — redireciona para `/` se não autenticado

## Notas de Implementação

- Username format: `{adjective}-{4 chars random}` (ex: `swift-3x9k`)
- Password: 10 chars alfanumérico case-sensitive
- MASTER_PASSWORD não é uma senha de usuário — é apenas para o endpoint admin
- Admin UI não precisa existir — uso via curl/postman ou script é suficiente para MVP

## QA Results

### Gate Decision: CONCERNS
**Revisor:** Quinn (QA Agent) | **Data:** 2026-03-19

#### Problemas a Corrigir
1. **[HIGH]** `src/middleware.ts` — importa `cookies` de `next/headers` que não existe no Edge Runtime (runtime padrão de middleware Next.js). Fix: usar `getIronSession(request, NextResponse.next(), sessionOptions)` — remover import de `next/headers` do middleware.
2. **[MEDIUM]** `src/lib/generate-credentials.ts` — `Math.random()` não é criptograficamente seguro. Fix: usar `crypto.randomBytes()` do Node.js para gerar os caracteres aleatórios.

#### O que passou ✅
- Rotas de auth completas (login, logout, admin/users)
- Bcrypt 10 rounds correto
- Mensagem de erro idêntica para user/senha inválidos (sem user enumeration)
- `x-master-password` header para admin
- LoginForm com UX correta (loading, role="alert", required)
- lint ✅ | typecheck ✅ | build ✅
