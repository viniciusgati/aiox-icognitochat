# Story 1.4 — Chat em Tempo Real com Criptografia E2E

**Status:** Done
**Epic:** 1 — IcognitoChat MVP
**Story:** 1.4
**Depende de:** 1.3

---

## Descrição

Como usuário, quero enviar e receber mensagens em tempo real numa sala, com criptografia de ponta a ponta via Web Crypto API, para que ninguém além dos participantes da sala possa ler o conteúdo.

---

## Critérios de Aceitação

- [ ] Página `/chat/[roomId]` exibe histórico de mensagens da sessão + input para envio
- [ ] Mensagens são criptografadas no browser antes de enviar via WebSocket
- [ ] Servidor recebe e retransmite `{ciphertext, iv, username, timestamp}` — NUNCA lê o conteúdo
- [ ] Mensagens são descriptografadas no browser do receptor
- [ ] Chave de criptografia derivada do `roomId` via PBKDF2 (Web Crypto API) — AES-256-GCM
- [ ] Ao entrar na sala, usuário vê apenas mensagens da sessão atual (não há histórico persistido)
- [ ] Indicador de usuários online na sala (via Socket.io presence)
- [ ] Enter envia mensagem, Shift+Enter quebra linha
- [ ] Mensagens mostram: username, conteúdo descriptografado, hora

## Notas de Segurança

- `deriveRoomKey`: usa `PBKDF2` com salt fixo (`icognito-v1`), 100k iterations, SHA-256
- Chave derivada fica apenas em memória JS — nunca em localStorage
- IV é gerado aleatório a cada mensagem (`crypto.getRandomValues`)
- Servidor armazena mensagens em `Map<roomId, Message[]>` — sem SQLite para mensagens

**Notas advisory (não bloqueiam):**
- [LOW] Salt fixo `icognito-v1` — mesmo roomId em deployments diferentes terá mesma chave. Melhoria futura: salt por deployment.
- [LOW] `username` no payload não validado servidor-lado — spoofing de sender possível. Aceitável MVP.

### Completion Notes
- PBKDF2 com salt `icognito-v1`, 100k iterações, SHA-256, AES-GCM 256-bit
- IV gerado por `crypto.getRandomValues` a cada mensagem
- Chave derivada fica apenas em memória JS (keyRef) — nunca persistida
- Servidor nunca acessa plaintext: relay de `{ciphertext, iv, username, timestamp}`
- Presença via `Map<roomId, Map<socketId, username>>` — emite `room-users` count
- `socket.to(roomId)` para relay (excluindo sender); sender faz update otimista
- Fix de TypeScript: `Array.from(Uint8Array, ...)` em vez de spread (target ES2015 constraint)
