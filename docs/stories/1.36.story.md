# Story 1.36 — Contato com o Admin (Usuário → Admin)

## Status: Ready for Review

## Story
Como usuário, quero poder enviar uma mensagem direta ao administrador de dentro do chat, para reportar problemas, pedir ajuda ou fazer solicitações — sem precisar sair da aplicação.

## Contexto Técnico
Atualmente a comunicação é **unidirecional**: o admin envia notificações push para os usuários, mas não existe canal para o usuário iniciar contato. Esta story implementa o sentido inverso: um formulário simples na UI do chat que persiste a mensagem no banco de dados e notifica o admin em tempo real via Socket.IO (e push notification, se subscrito).

A feature não é uma sala de chat — é uma caixa de entrada administrativa. O admin visualiza e responde (via push notification existente) pelo painel `/admin`.

## Acceptance Criteria

### Botão de Contato na UI
- [ ] Exibir botão "Falar com o Admin" na barra lateral ou no header do chat hub (`/chat`)
- [ ] Botão abre modal com campo de texto (máx. 500 caracteres) e botão "Enviar"
- [ ] Mostrar contador de caracteres restantes no modal
- [ ] Botão "Enviar" desabilitado se campo vazio ou exceder limite
- [ ] Após envio com sucesso: fechar modal e exibir toast "Mensagem enviada ao admin ✓"
- [ ] Após erro: exibir toast de erro sem fechar o modal (mensagem preservada)

### API de Mensagens Admin
- [ ] `POST /api/contact-admin` — autenticado (requer sessão de usuário), persiste mensagem no DB
  - Body: `{ message: string }` (1–500 chars)
  - Response: `{ id: number, created_at: string }`
- [ ] Validar tamanho da mensagem no servidor (400 se inválida, 401 se não autenticado)
- [ ] Rate limit: máx. 3 mensagens por usuário por hora (429 se exceder)

### Tabela no Banco de Dados
- [ ] Nova tabela `admin_messages`: `id`, `user_id` (FK → users), `message` (TEXT), `read` (BOOLEAN DEFAULT 0), `created_at`
- [ ] Migration aplicada via `db.ts` (along with existing schema init)

### Notificação em Tempo Real para o Admin
- [ ] Ao receber nova mensagem, servidor emite evento Socket.IO `admin:new-message` para sockets autenticados como admin
- [ ] Se admin tiver push subscription ativa, enviar push notification: "📩 Nova mensagem de {username}"

### Painel Admin — Aba "Mensagens"
- [ ] Nova aba "Mensagens" no painel `/admin` (entre "Notificações" e "Configurações")
- [ ] Lista mensagens com: username, preview (80 chars), data/hora relativa, badge "Novo" se não lida
- [ ] Clicar na mensagem expande o texto completo e marca como lida (`read = 1`)
- [ ] Contador de mensagens não lidas no título da aba: "Mensagens (3)"
- [ ] Botão "Marcar todas como lidas"
- [ ] Botão "Responder" ao lado de cada mensagem → abre modal de envio de push notification pré-preenchido com o `user_id` e foco no campo de mensagem
- [ ] Endpoint `GET /api/auth/admin/messages` — retorna lista paginada (20 por página), ordenada por `created_at DESC`
- [ ] Endpoint `PATCH /api/auth/admin/messages/[id]` — marca mensagem como lida
- [ ] Endpoint `PATCH /api/auth/admin/messages` — marca todas como lidas

### Badge de Notificação no Admin Panel
- [ ] Se houver mensagens não lidas, exibir badge vermelho com contagem no link/botão de acesso ao painel admin (caso exista na UI)

## Dev Notes

### Schema Migration
```sql
CREATE TABLE IF NOT EXISTS admin_messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  message TEXT NOT NULL,
  read INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_admin_messages_read ON admin_messages(read);
CREATE INDEX IF NOT EXISTS idx_admin_messages_user ON admin_messages(user_id);
```

### Rate Limiting
Usar mapa in-memory `Map<userId, timestamp[]>` (simples, sem Redis), janela de 1h. Persistir estado no processo Node.js — não requer dependência nova.
