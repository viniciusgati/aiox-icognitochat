# Story 1.20 — Validação de Sessão contra Banco de Dados

**Status:** Ready
**Epic:** 1 — IcognitoChat MVP
**Story:** 1.20
**Depende de:** 1.2, 1.11

---

## Descrição

Como usuário do sistema, quero que uma sessão inválida (cujo usuário foi deletado do banco) seja detectada e encerrada automaticamente na próxima navegação — especialmente após um evento de auto-destruição — para que sessões fantasma não permitam acesso a rotas protegidas de um servidor que foi limpo.

---

## Contexto Técnico

O middleware atual (`src/middleware.ts`) verifica apenas `session.isLoggedIn` no cookie iron-session — **não consulta o banco**. Isso é correto para performance em condições normais, mas cria uma lacuna após a Story 1.11 (auto-destruição):

- `destroyAllData()` deleta todos os usuários do banco
- Cookies existentes ainda têm `{ isLoggedIn: true, userId: X }`
- Middleware deixa o usuário passar → acessa `/chat` com sessão fantasma
- Estado persiste por até 7 dias (maxAge do cookie)

O middleware roda no **Edge runtime** do Next.js — sem acesso ao SQLite (Node.js only). A validação contra banco deve ocorrer em outro ponto.

### Solução: endpoint `GET /api/auth/me` + verificação no hub

Criar um endpoint leve que valida `userId` da sessão contra o banco. O hub `/chat` chama esse endpoint ao montar — se retornar `401`, destrói a sessão local e redireciona para `/`.

Esse padrão é simples, não requer mudança no middleware, e cobre o caso de sessão fantasma pós-destruição sem adicionar uma consulta ao banco em cada request.

---

## Critérios de Aceitação

- [ ] `GET /api/auth/me` retorna `{ username }` com status `200` se o `userId` da sessão existe no banco
- [ ] `GET /api/auth/me` retorna `401` e destrói a sessão se o usuário não existe no banco (ou se não está logado)
- [ ] O hub `/chat` (`src/app/chat/page.tsx`) verifica `GET /api/auth/me` ao montar via `useEffect` no client
- [ ] Se `/api/auth/me` retornar `401`, o hub chama `POST /api/auth/logout` e redireciona para `/`
- [ ] A verificação não bloqueia a renderização inicial do hub (executa após mount, não no server)
- [ ] Usuários com sessão válida (usuário existe no banco) não percebem nenhuma mudança de comportamento

---

## Tarefas

- [ ] Criar `src/app/api/auth/me/route.ts`:
  - Lê `session.userId` da iron-session
  - Se não logado ou sem `userId`: destrói sessão, retorna `401`
  - Consulta `SELECT id FROM users WHERE id = ?` com `userId`
  - Se usuário não encontrado: destrói sessão, retorna `401`
  - Se encontrado: retorna `{ username: session.username }` com `200`

- [ ] Atualizar `src/app/chat/page.tsx`:
  - Converter para Client Component (`'use client'`) ou extrair a verificação em um componente filho client

  - Enquanto a verificação não completa: exibir o hub normalmente (não bloquear renderização)

## Notas de Implementação

```typescript
// src/app/api/auth/me/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { getIronSession } from 'iron-session'
import { cookies } from 'next/headers'
import { sessionOptions, SessionData } from '@/lib/session'
import db from '@/lib/db'

export async function GET(req: NextRequest) {
  const session = await getIronSession<SessionData>(await cookies(), sessionOptions)

  if (!session.isLoggedIn || !session.userId) {
    session.destroy()
    return NextResponse.json({ error: 'Não autenticado' }, { status: 401 })
  }

  const user = db.prepare('SELECT id FROM users WHERE id = ?').get(session.userId)

  if (!user) {
    await session.destroy()
    return NextResponse.json({ error: 'Sessão inválida' }, { status: 401 })
  }

  return NextResponse.json({ username: session.username })
}
```

```typescript
// src/app/chat/page.tsx — verificação de sessão ao montar
'use client'

import { useEffect } from 'react'
import { useRouter } from 'next/navigation'
// ... demais imports

export default function ChatPage() {
  const router = useRouter()

  useEffect(() => {
    fetch('/api/auth/me').then((res) => {
      if (!res.ok) {
        fetch('/api/auth/logout', { method: 'POST' }).finally(() => {
          router.push('/')
        })
      }
    })
  }, [router])

  // ... resto do componente renderiza normalmente
}
```

### Fluxo pós-destruição (Story 1.11)

```
Admin aciona POST /api/auth/admin/destroy
  → banco limpo, sockets desconectados

Usuário com sessão fantasma acessa /chat
  → hub renderiza (sem bloqueio)
  → useEffect: GET /api/auth/me → userId não existe → 401
  → POST /api/auth/logout → cookie destruído
  → router.push('/') → tela de login
  → usuário não consegue logar (tabela users vazia)
```
