# Story 1.37 — Feedback de Redirecionamento de Salas

## Status: Ready for Dev

## Story
Como usuário, quando tento acessar uma sala e sou redirecionado, quero ver uma mensagem explicando o motivo — em vez de ser silenciosamente jogado para outra tela sem entender o que aconteceu.

## Contexto Técnico

Existem dois redirecionamentos silenciosos em `src/app/chat/[roomId]/page.tsx`:

**Causa A — `admin_only_chat` ativado (linha 26):**
```ts
if (!session.isAdmin && getSetting('admin_only_chat') === '1' && roomId !== 'general') {
  redirect('/chat/general')  // sem aviso ao usuário
}
```
Não-admins que acessam qualquer link de sala são silenciosamente jogados para o Geral sem saber por quê.

**Causa B — Sala não existe no banco (linha 35):**
```ts
if (!room) {
  redirect('/chat')  // sem aviso ao usuário
}
```
Acontece com salas efêmeras encerradas (deletadas quando o último usuário sai) e slugs inválidos. O usuário cai na lista de salas sem entender o que aconteceu.

## Acceptance Criteria

### Causa A — Modo suporte ativo (admin_only_chat)
- [ ] Ao ser redirecionado para `/chat/general` por restrição de admin, o usuário vê um banner/toast: "Acesso restrito — apenas a sala Geral está disponível neste momento"
- [ ] O banner aparece automaticamente ao entrar no Geral por redirecionamento (não ao navegar normalmente)
- [ ] O banner desaparece após 5 segundos ou ao ser dispensado manualmente

### Causa B — Sala não encontrada
- [ ] Ao tentar acessar uma sala inexistente, o usuário é redirecionado para `/chat` com um toast: "Sala não encontrada ou já foi encerrada"
- [ ] Para salas efêmeras: a mensagem é "Esta sala efêmera foi encerrada"
- [ ] O toast aparece automaticamente na tela de lista de salas e desaparece após 5 segundos

### Mecanismo de passagem de contexto
- [ ] O redirecionamento usa query params para comunicar o motivo:
  - `/chat/general?reason=restricted` → banner de restrição
  - `/chat?reason=not-found` → toast de sala não encontrada
  - `/chat?reason=ephemeral-closed` → toast de sala efêmera encerrada
- [ ] Os componentes receptores leem o `reason` da URL e exibem o feedback apropriado
- [ ] Após exibir o feedback, a URL é limpa (replace state) para não reaparecer no refresh
