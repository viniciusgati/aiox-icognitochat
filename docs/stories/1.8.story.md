# Story 1.8 — Redirect para Sala Efêmera Após Login

**Status:** Ready for Review
**Epic:** 1 — IcognitoChat MVP
**Story:** 1.8
**Depende de:** 1.7

---

## Descrição

Como usuário que recebe um link de sala efêmera, quero que, ao clicar no link e fazer login, seja redirecionado diretamente para a sala — e não para o hub `/chat` — para não precisar clicar no link novamente depois de autenticado.

---

## Contexto Técnico

O problema ocorre em duas etapas:

1. **Middleware (`src/middleware.ts`)** intercepta a rota `/chat/[slug]` quando o usuário não está autenticado e redireciona para `/` — sem preservar a URL original.
2. **`LoginForm.tsx`** após login bem-sucedido sempre faz `router.push('/chat')` — ignorando qualquer destino original.

O fluxo correto: middleware passa o destino como `?callbackUrl=...` na query, e o `LoginForm` redireciona para esse valor após autenticação.

---

## Critérios de Aceitação

- [x] Ao acessar `/chat/xk9m-2p7q` sem estar logado, o middleware redireciona para `/?callbackUrl=%2Fchat%2Fxk9m-2p7q`
- [x] Após login bem-sucedido, se `callbackUrl` estiver presente na query string, o usuário é redirecionado para essa URL
- [x] Se `callbackUrl` não estiver presente, comportamento padrão: redireciona para `/chat`
- [x] `callbackUrl` é validado: apenas URLs relativas começando com `/chat` são aceitas (previne open redirect)
- [x] O fluxo funciona tanto para salas efêmeras quanto para salas persistentes acessadas sem login

## Notas de Implementação

```typescript
// middleware.ts — preservar URL original
const callbackUrl = encodeURIComponent(req.nextUrl.pathname)
return NextResponse.redirect(new URL(`/?callbackUrl=${callbackUrl}`, req.url))

// LoginForm.tsx — ler e validar callbackUrl
const searchParams = useSearchParams()
const callbackUrl = searchParams.get('callbackUrl')
const safeRedirect = callbackUrl?.startsWith('/chat') ? callbackUrl : '/chat'
router.push(safeRedirect)
```
