## Descrição

Como operador, quero um endpoint de health check que verifique o status do banco e do servidor, para que o Railway possa monitorar se o serviço está saudável e evitar tratar um deploy quebrado como bem-sucedido.

---

## Contexto Técnico

Railway suporta health checks via HTTP antes de considerar um deploy como live. Sem isso, o Railway assume que o deploy funcionou assim que o processo sobe — mesmo que o banco não esteja acessível ou haja erro de inicialização.

O endpoint deve ser leve (sem autenticação, sem lógica pesada) e retornar informações suficientes para diagnóstico.

---

## Critérios de Aceitação

- [ ] `GET /api/health` retorna HTTP 200 com JSON quando tudo está OK
- [ ] Retorna HTTP 503 se o banco SQLite não estiver acessível
- [ ] Response body inclui: `{ status, db, uptime, timestamp }`
- [ ] Endpoint não requer autenticação
- [ ] Resposta em menos de 100ms
- [ ] O endpoint pode ser configurado no Railway como health check path

---

## Notas de Implementação

```typescript
// GET /api/health
import { NextResponse } from 'next/server'
import db from '@/lib/db'

export async function GET() {
  let dbStatus: 'ok' | 'error' = 'ok'
  try {
    db.prepare('SELECT 1').get()
  } catch {
    dbStatus = 'error'
  }

  const status = dbStatus === 'ok' ? 'ok' : 'degraded'
  return NextResponse.json(
    { status, db: dbStatus, uptime: process.uptime(), timestamp: new Date().toISOString() },
    { status: status === 'ok' ? 200 : 503 }
  )
}
```
