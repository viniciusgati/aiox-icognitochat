# Story 1.26 — Upload de imagens na sala (E2E, WebP, max 10/sala)

## Status: InProgress

## Story
Como usuário, quero enviar imagens na sala, para que eu possa compartilhar conteúdo visual de forma segura e criptografada.

## Acceptance Criteria
- [ ] Botão de imagem na área de input
- [ ] Conversão automática para WebP (max 1920px, qualidade 0.85) no cliente antes do envio
- [ ] Imagem criptografada com a chave da sala (AES-GCM) antes de sair do navegador
- [ ] Upload para `/api/rooms/[roomId]/images` — servidor nunca vê conteúdo em claro
- [ ] Limite de 10 imagens por sala — erro 429 ao ultrapassar
- [ ] Relay via Socket.io: `send-image` → `receive-image` com imageId + iv
- [ ] Receptor faz fetch do blob criptografado, decifra e exibe na bolha de mensagem
- [ ] Imagens visíveis somente para usuários online no momento do envio (sem histórico)
- [ ] Limpeza de blob URLs no cleanup

## Tasks
- [ ] crypto.ts: `encryptBinary` e `decryptBinary`
- [ ] db.ts: tabela `room_images` + migração + helper `deleteRoomImages`
- [ ] API POST `/api/rooms/[roomId]/images`: upload com limite
- [ ] API GET `/api/rooms/[roomId]/images/[imageId]`: servir blob criptografado
- [ ] server.ts: relay `send-image` → `receive-image`
- [ ] socket-client.ts: `sendImage`, handler `receive-image`, cleanup de blob URLs
- [ ] ChatWindow.tsx: botão de imagem + input file oculto
- [ ] MessageBubble.tsx: renderizar imagem quando `imageSrc` presente

### AC Verification

| AC | Status | Observação |
|----|--------|------------|
| Botão de imagem na área de input | ✅ | `fileInputRef` + botão `onClick → fileInputRef.current?.click()` em ChatWindow |
| Conversão WebP (max 1920px, qualidade 0.85) no cliente | ✅ | `createImageBitmap` + `canvas.toBlob('image/webp', 0.85)` em `sendImage` |
| Imagem criptografada AES-GCM antes de sair | ✅ | `encryptBinary(keyRef.current, arrayBuffer)` — `crypto.ts` usa AES-GCM 256-bit |
| Upload para `/api/rooms/[roomId]/images` — servidor não vê plaintext | ✅ | `Content-Type: application/octet-stream`, server salva blob criptografado direto |
| Limite 10 imagens/sala → 429 | ✅ | `MAX_IMAGES_PER_ROOM = 10`, `COUNT(*)` antes do insert, status 429 |
| Relay `send-image` → `receive-image` com `imageId + iv` | ✅ | `server.ts` faz `socket.to(roomId).emit('receive-image', ...)` |
| Receptor faz fetch, decifra e exibe na bolha | ✅ | `receive-image` handler: fetch → `decryptBinary` → `URL.createObjectURL` → `imageSrc` em MessageBubble |
| Imagens visíveis só para online no momento | ✅ | Sem histórico de mensagens no join, relay apenas em tempo real |
| Limpeza de blob URLs no cleanup | ✅ | `urls.forEach((u) => URL.revokeObjectURL(u))` no cleanup do `useEffect` |

### Security Analysis

| Vetor | Status | Detalhe |
|-------|--------|---------|
| Path traversal no imageId | ✅ | Regex `/^[0-9a-f-]{36}$/` antes de `path.join` |
| Acesso cross-room | ✅ | JOIN `rooms` + `room_images` valida que `imageId` pertence ao `roomId` solicitado |
| Auth em POST e GET | ✅ | `getIronSession` com guard `isLoggedIn` em ambas as rotas |
| Double-check de tamanho | ✅ | Verifica `content-length` header E `buffer.byteLength` (previne bypass) |
| Limpeza em `deleteRoom` | ✅ | `deleteRoom` chama `deleteRoomImages` antes de deletar do DB; CASCADE na FK |

### Notes
- Implementação E2E sólida: servidor nunca tem acesso ao conteúdo das imagens.
- Imagem própria exibida imediatamente via blob URL do plaintext (`URL.createObjectURL(webpBlob)`), sem round-trip.
- Falha silenciosa no `receive-image` (`if (!res.ok) return`) — aceitável dado o contexto efêmero, mas o usuário não recebe feedback visual de falha.
