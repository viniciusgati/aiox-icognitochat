# Story 1.38 — Canal de Vendas: Chat Direto Usuário ↔ Admin

## Status: Ready for Dev

## Story
Como usuário, quero ter um canal de chat privado e em tempo real com o admin para tratar assuntos de vendas — sem perder o acesso às salas normais com outros usuários.

Como admin, quero ver todas as conversas de vendas abertas em um único lugar e responder diretamente via chat, sem precisar usar push notifications.

## Contexto Técnico

A Story 1.36 implementou um formulário de contato unidirecional (usuário → admin, admin responde por push). Isso é insuficiente para vendas, que exigem conversa em tempo real e múltiplas trocas.

O `admin_only_chat` (configuração existente) **não deve ser alterado** — ele continua servindo para cenários de suporte puro onde não há salas entre usuários. Esta story cria uma camada paralela: salas privadas de vendas que coexistem com as salas normais.

### Arquitetura
Cada usuário tem uma **sala de vendas privada** persistente com o admin:
- Slug: `vendas-{userId}` (ex: `vendas-42`)
- Criada automaticamente no primeiro contato
- Visível apenas para o dono e admins
- Listada no painel admin como "Fila de Vendas"
- Não aparece na lista de salas normais do `/chat`

O botão "💬 Suporte" da Story 1.36 passa a abrir esse canal de chat (em vez do modal de formulário), mantendo toda a infraestrutura de Socket.IO e mensagens já existente.

## Acceptance Criteria

### Canal de vendas por usuário
- [ ] Ao clicar em "💬 Suporte", o usuário é direcionado para sua sala de vendas privada (`/chat/vendas-{userId}`)
- [ ] Se a sala ainda não existe, é criada automaticamente no banco antes do redirect
- [ ] A sala é marcada como `is_private = 1` e com `created_by` = userId do usuário
- [ ] A sala NÃO aparece na listagem pública de `/api/rooms`
- [ ] O admin tem acesso a todas as salas `vendas-*` independente de privacidade

### Experiência do usuário na sala de vendas
- [ ] Interface igual às salas normais (ChatWindow existente) — sem mudanças no componente
- [ ] Cabeçalho da sala exibe "Vendas — Atendimento" em vez do slug técnico
- [ ] Botão "Voltar" leva de volta ao `/chat` (lista de salas)
- [ ] Mensagens são persistidas normalmente (TTL global se configurado)

### Painel Admin — Fila de Vendas
- [ ] Nova aba "Vendas" no painel `/admin` (após "Mensagens")
- [ ] Lista todas as salas `vendas-*` com: username do usuário, última mensagem (preview 60 chars), data/hora, badge "Novo" se houver mensagens não lidas pelo admin
- [ ] Clicar em uma conversa abre diretamente `/chat/vendas-{userId}` (admin entra como participante)
- [ ] Contador de conversas com atividade recente (últimas 24h) no título da aba
- [ ] Endpoint `GET /api/auth/admin/sales` — lista salas vendas-* com metadados

### Notificação ao admin
- [ ] Quando usuário envia primeira mensagem na sala de vendas, emitir Socket.IO `admin:sales-message` com `{ userId, username, preview }`
- [ ] Se admin tiver push subscription, enviar push: "🛒 {username} iniciou uma conversa de vendas"

### Coexistência com admin_only_chat
- [ ] Quando `admin_only_chat = '1'`: usuários ainda são bloqueados nas salas normais, MAS o botão "💬 Suporte" continua visível e funcional
- [ ] A sala de vendas `vendas-{userId}` é acessível mesmo com `admin_only_chat` ativo
- [ ] Em `[roomId]/page.tsx`, salas com slug `vendas-*` são excluídas da verificação de `admin_only_chat`

### Migração do botão Suporte
- [ ] O botão "💬 Suporte" em `RoomList.tsx` passa a redirecionar para `/chat/vendas-{userId}` via `router.push()`
- [ ] O componente `ContactAdminModal.tsx` da Story 1.36 é mantido (pode ser usado em outros contextos), mas não é mais acionado pelo botão Suporte
- [ ] A Story 1.36 (formulário de contato por texto) continua funcional como canal alternativo — não é removida

## Dev Notes

### Criação automática da sala de vendas
```ts
// src/app/api/sales-room/route.ts (novo) — GET ou POST
// Retorna o slug da sala de vendas do usuário autenticado, criando-a se necessário
const slug = `vendas-${session.userId}`
const existing = db.prepare('SELECT slug FROM rooms WHERE slug = ?').get(slug)
if (!existing) {
  db.prepare(`
    INSERT INTO rooms (slug, name, description, is_private, created_by)
    VALUES (?, ?, ?, 1, ?)
  `).run(slug, `Vendas — Atendimento`, `Canal de vendas privado`, session.userId)
}
return NextResponse.json({ slug })
```

### Exclusão de admin_only_chat para salas de vendas
```ts
// src/app/chat/[roomId]/page.tsx
if (!session.isAdmin && getSetting('admin_only_chat') === '1'
    && roomId !== 'general'
    && !roomId.startsWith('vendas-')) {   // ← exceção
  redirect('/chat/general?reason=restricted')
}
```

### Acesso admin às salas privadas
```ts
// src/app/chat/[roomId]/page.tsx
const room = db.prepare(`
  SELECT name, is_ephemeral, message_ttl_seconds, is_private, created_by
  FROM rooms WHERE slug = ?
`).get(roomId)

if (!room) redirect('/chat?reason=not-found')

// Admin acessa qualquer sala; não-admin acessa apenas salas públicas ou as suas próprias
if (room.is_private && !session.isAdmin && room.created_by !== session.userId) {
  redirect('/chat')
}
```

### API de listagem para admin
```ts
// GET /api/auth/admin/sales
// Retorna salas vendas-* com última mensagem e contagem de mensagens não lidas pelo admin
SELECT r.slug, r.created_by, u.username,
       (SELECT content FROM messages WHERE room_id = r.id ORDER BY created_at DESC LIMIT 1) as last_message,
       (SELECT created_at FROM messages WHERE room_id = r.id ORDER BY created_at DESC LIMIT 1) as last_activity
FROM rooms r
JOIN users u ON u.id = r.created_by
WHERE r.slug LIKE 'vendas-%'
ORDER BY last_activity DESC NULLS LAST
```
